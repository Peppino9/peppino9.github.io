Ekonex: one company, three audiences

Not the loudest story in this portfolio, but a site that reaches the people the company needs, and they see the results.

Client

Where

Ekonex is an authorised car recycler that also sells used cars and parts, refills LPG and fits tyres. Different people need different things from that one company, so the three language versions of the site are not translations of each other. Each is built to be found by its own audience, with both SEO and GEO in mind. SEO gets the site found in search results. Chapter 5SoftwareTeam project at Malmö University, spring 2024

FutQuiz

A football quiz in the style of Kahoot, and my first time building software with a team of five.

Team
5 developers
When
March–May 2024
Budget
1,100 hours, run in Scrum sprints
My part
Frontend, quiz flow and CI/CD

Players pick a difficulty (easy, medium or hard) and a category, answer ten questions against a 30-second clock and land on a leaderboard. Players can also suggest their own questions, and an admin approves them into the live question bank.

I laid the first stones: the database connection, the quiz flow, sign-up and sign-in with error handling, the progress bar and menu, the admin views, the user list and logout. I also set up CI/CD with integration testing, so nothing reached the main branch unless every test passed. Most of the visual design is CSS, with JavaScript added on top as progressive enhancement, so the interface still holds together when JavaScript is off.

We ran the project like a real one. There were requirements prioritised with MoSCoW, a design document with system, sequence and use-case diagrams and an ERD, a test document, time reports, and four review sessions where we presented to supervisors and gave feedback to other teams.

My individual deep-dive

I wrote the team's usability analysis. I evaluated the interface against Jakob Nielsen's ten heuristics at two checkpoints and turned the findings into concrete changes: a visible timer and progress bar, familiar button labels, password rules shown up front, and one consistent colour and type system.

Chapter 6SoftwareClient project for NSR AB, autumn 2025

Avfallskompassen

A planning tool where property owners draw their waste room to scale, place the bins and see what it costs, built for NSR in north-western Skåne.

Client
NSR AB
Team
8 developers
When
Sept 2025 – Jan 2026
My part
Auth UI, dashboard, admin tools, room versions

When a property owner plans a waste room (miljörum), the questions are practical. Do the bins fit? Can the door open? Are we paying for more volume than we need? Avfallskompassen answers them visually. You set the room's size, add doors, drag in bins for each fraction, and the tool shows the yearly cost, the total bin volume, the estimated CO₂ savings and how the property compares with similar ones.

Eight of us built it as a React and TypeScript frontend on a Spring Boot API with PostgreSQL. It had JWT authentication and a CI/CD pipeline in GitHub Actions that ran the backend and frontend tests on every push.

What I built

  • The login page and its connection to the backend, and a fix so the navigation bar reacts to login state.
  • The dashboard, and a rework of the UI so it follows NSR's visual identity.
  • A new planning sidebar with dropdown sections and inline error messages instead of browser alerts, plus mobile fixes.
  • The admin side: the admin dashboard, the planning editor and user detail views.
  • Versioning of waste rooms: admins can save, list, switch between and delete versions, with a loading view while they load.
  • The pop-up that lets a user pick which property to plan for, and fixes to the cost analysis and to how plans are identified and stored.

Room plans saved by the app as thumbnails during development. Each one records the room's dimensions, doors and bin placement.

Chapter 7SoftwareBachelor's thesis with Rejlers AB, spring 2026

ALMA

“Fråga ALMA. Få svar.” An AI assistant that answers residents' questions about a railway expansion, using only the official documents.

With
Abdullah Hamid, Rejlers AB
Where
Malmö University
Case
Lund, four tracks (Trafikverket)
Runs on
Docker on Railway

The problem

Trafikverket's project to expand the railway through Lund to four tracks produces hundreds of pages of consultation documents. They are public, but almost impossible for a resident to read. Rejlers coordinates communication with the people affected and answers the same factual questions every day.

What we built

ALMA indexes the project's PDFs and the public StoryMaps pages about the project, retrieves the passages that match a question and writes a short answer in Swedish, with the sources listed. My thesis partner Abdullah and I built it together.

The first version was a Streamlit prototype. Retrieval was not good enough, so I rebuilt it. The chunk size went from 1,500 down to 500 so that each chunk covers one idea. Keyword search (BM25) now runs next to the vector search, so project codes and abbreviations are not lost, and a reranker picks the final ten passages. The interface became a React app on a FastAPI backend, deployed with Docker on Railway.

Testing it on real people

A demo is not a result, so the thesis measured three things. Four professionals at Rejlers rated the answers for accuracy and completeness. We checked whether automatic metrics agreed with them. And nine people connected to the project area compared ALMA with searching the documents on their own.

  • RQ1: AccuracyGood on standard questions, weaker on complex onesALMA reached acceptable accuracy on predefined tasks (3.25–4.25 of 5) but dropped on the professionals' own questions (2.33–3.33). It simplified rather than invented, and lost technical nuance along the way.
  • RQ2: MetricsAutomatic scores can't replace expertsNone of LIX, Ragas Faithfulness or Answer Relevancy tracked the experts' ratings. Answer Relevancy returned zero for 40% of the Swedish answers.
  • RQ3: TrustA trust gap5 of 9 residents felt confident in answers that the professionals had flagged as partly unreliable. A well-presented AI earns more trust than its accuracy justifies.

Chapter 8WebsitesFull circle, client project, 2026

AM Mättjänst

A website for a two-person surveying firm in Skåne. The same kind of client I started with, but this time every part is written in code.

Client
AM Mättjänst AB
Area
Skåne
Built with
Astro 7, TypeScript
Year
2026

AM Mättjänst stakes out houses before the ground is dug and checks their position for the building permit (husutstakning and lägeskontroll). Their customers are homeowners with a fresh permit and building contractors. Both want the same things: a clear price, proof that the job was done right, and an easy way to book.

What I built

  • Brand guidelines turned into design tokens, with a light and a dark theme.
  • Static Astro pages plus one server route for bookings. It checks the fields, stops bots with a honeypot and emails the request, with drawings attached (PDF, DWG, DXF or images, up to 20 MB), through Resend.
  • One price list in code, excluding VAT. A switch shows consumer prices including VAT by default, as Swedish pricing law requires.
  • Local pages for eight municipalities, schema.org data, a sitemap and an llms.txt, so search engines and AI assistants describe the firm correctly.
  • Pages that work without JavaScript. Without it, the form still posts and the server redirects.
